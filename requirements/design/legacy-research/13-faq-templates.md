## 0. 結論：既にプレースホルダ化されたテンプレート集。そのまま投入できる。

318件のFAQが「カテゴリ／問い合わせ内容／回答テンプレ」の3列で整理済み。
回答は**メール定型（宛先・挨拶・本文・締め）で、会社名等が `○○○○` でプレースホルダ化**されている。
→ **新システムの問い合わせテンプレート機能（旧 P4-14 → R4 `NotificationTemplate`）にほぼそのまま投入できる**
（ただし Rails版の現行 `NotificationTemplate` は「件名＋本文の定型文」までで、カテゴリ・差し込み変数・返信画面での選択は未実装。§3）。

## 2. 回答テンプレートの型

**共通構造（メール定型・約25行）**

```
○○○○（会社名プレースホルダ）
ご担当者様

お世話になっております。
#BridgePlus運用サポート …（挨拶）

【本文】…（質問への回答）…

上記ご質問への回答になればと思いますが、ご不明点ございましたら
本メールのご返信にて、改めてご質問のほど、よろしくお願いいたします。
（署名）
```

**プレースホルダ**：`○○○○`（会社名／顧客名）。新システムでは差し込み変数
（例 `{{customer_name}}` / `{{store_name}}`）へ対応させる。
**Rails版注記**: 差し込み変数の展開ロジックは未実装。実装するなら Ruby の `String#%`（`%{customer_name}` 形式）か Liquid gem 等を候補とし、
変数の供給元は `Inquiry` → `Order` → `Customer` / `Store`（`customer.name` / `store.store_name` / `order.order_number` / `inquiry.inquiry_number`）。

## 3. 新システムへの投入方針（旧 P4-14 → R4 実装との突合。2026-08-19）

| # | 対応 | Rails版 実装状況（2026-08-19） | 想定フェーズ |
|---|---|---|---|
| F-1 | **12カテゴリ → 問い合わせカテゴリマスタ**（inquiries の分類。既存の問い合わせ機能に分類軸を追加） | **未実装**。`NotificationTemplate` にカテゴリ列なし。`inquiries.category`（後確/制作対応/検収コール/アフター問合せ）は掲示板統合の種別であり本FAQの分類とは別軸 → テンプレ側に `category`（またはタグ）列の追加が必要 | R4後続 / R6（04 で未決） |
| F-2 | **318件のQ&A → 問い合わせテンプレート**（basic-design §17-4。テンプレート管理 CRUD へ初期データ投入） | CRUD は **実装済み（R4）**: `Admin::NotificationTemplatesController` ＋ `NotificationTemplate`（`template_type: inquiry` で登録可）。**初期データ投入（seed / rake）は未実装** | 投入は R7（データ投入）または R4後続 |
| F-3 | プレースホルダ `○○○○` を**差し込み変数**へ変換（顧客名・店舗名・案件番号 等） | **未実装**（置換ロジックなし。テンプレ本文はコピーのみ） | R4後続 / R6 |
| F-4 | テンプレートは**問い合わせ返信時に選択・差し込み**（現行の「回答集から探してコピペ」を廃止） | **未実装**。`Admin::InquiryMessagesController#create` は `body`・添付のみ。返信フォーム（`admin/inquiries/show.html.erb`）にテンプレ選択 UI なし。一斉通知側（`Admin::NotificationsController`）には同等の選択→コピー機構が実装済みなので**流用可能** | R4後続 / R6 |
| F-5 | 外部システムFAQである旨のタグ付け（新システム操作FAQと混在させない） | **未実装**（F-1 のカテゴリ/タグ列で兼ねる） | F-1 と同時 |

> **実装フェーズは 04 で未決**（04 R4「未実装ギャップ」・「次のアクション」5: 実装要否と実施フェーズ（R4後続 / R6 / R7）を 決定者・業務側に確認）。
> 本書は「投入方針」であり、上記の要否判断が済むまで実装に着手しない。

> **現行の運用**：BWが「回答集Excelから該当FAQを探してコピペ→会社名を手で置換」している。
> 新システムでは**テンプレート選択＋自動差し込み**で、探す・置換する手間を消す（内製化の目的と一致）。

## 4. 投入時の整形

| 課題 | 対応 |
|---|---|
| カテゴリ列が先頭行のみ（結合セル） | 各Q&Aにカテゴリを補完してから投入 |
| 回答本文の改行 | Markdown/プレーンの改行を保持（`notification_templates.body` は text） |
| プレースホルダの揺れ（`○○○○` の使われ方） | 会社名／担当者名／店舗名のどれかを判別して変数割当（要目視） |
| 外部システム固有の内容（アシスト管理画面URL等） | 移行時に有効性を確認（古いURL・仕様変更） |
| （Rails版追加）投入手段 | xlsx → CSV 化し rake タスク（例 `legacy:import_faq_templates`）または `db/seeds` から `NotificationTemplate.create!(template_type: "inquiry", ...)`。実データ（回答本文）は PII ではないが原資料は `private/` に置いたまま読み、リポジトリにはコミットしない（`pii-handling-rules.md` §2-2 の運用に準拠） |
