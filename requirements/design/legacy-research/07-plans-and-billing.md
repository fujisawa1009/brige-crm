## 1. 現行プラン体系（40種超・要集約）

現行は**プランが乱立**している。割引率（10〜40%）× 契約期間（[12]/[24]）の掛け算で膨張。

### 1-1. プラン系統（抜粋）

| 系統 | 価格帯 | 備考 |
|---|---|---|
| Linksα12 / α6 | 9,800〜29,800円 | スタートアップ/ノーマル/カスタマイズ/ベーシック |
| MEO単体 [12]/[24] | 6,000〜10,000円 | 10〜40%割引の5段階 |
| シンプル+MEOセット [12]/[24] | 13,780〜22,980円 | 10〜40%割引 |
| スタートアップ+MEOセット [12]/[24] | 14,880〜24,800円 | 10〜40%割引 |
| スタートアッププラン [12]/[24] | 8,880〜14,800円 | 10〜40%割引 |

> 割引×期間で**同一系統に5〜10のバリエーション**。合計40種超。

### 1-2. 集約方針（方針MTG 2026-04-23 ④）

- 現状：19,800〜39,800円の5プラン（実際は上記の通りさらに多い）
- **改修後：39,800 / 49,800 / 59,800 の3プランへ集約**（LTV最大化・優良顧客へシフト）

> **設計への示唆**：
> - 新システムの `plans` マスタは**3プランで設計**しつつ、**移行のため旧プランも保持**する必要がある。
> - 移行案件は旧プラン価格に紐づいたまま（既存契約の月額は変えられない）。
>   → `plans` に「新規受付可否フラグ」を持ち、**旧プランは受付停止・表示のみ**にする。
> - `contract_conditions`（契約条件バージョン）と同じ「過去は過去の条件を保持」の考え方。
> - プラン確定時期が未定（Q-背2）。**マスタ設計はプラン数に依存しない汎用構造**にしておく。
>
> **brige-crm 実装状況（R2 実装済み・2026-08-19 突合）**:
> - `Plan`（`plans`: `product_id` / `code`(20) / `name`(100) / `monthly_fee`(integer) / `is_active` / `sort_order`）＋管理UI `Admin::PlansController`。
>   商材（`Product`）配下にプランを持つ構造で、プラン数に依存しない。
> - 「新規受付可否フラグ」= `plans.is_active`（受付停止プランは `is_active: false` で保持・表示のみ）。
> - `Order` は `plan_id` を参照する（FK）。**月額料金のスナップショット（受注時点の `monthly_fee` を `orders` 側に保存する）カラムは無い**
>   → 旧プランの `monthly_fee` を後から変更すると既存契約の表示額が変わる。**Q-移15（月額料金スナップショット保存の要否）として R7 に持ち越し**
>   （04 R7 既知の未決事項）。移行時は「旧プランを `is_active: false` で全件投入し `orders.plan_id` を紐づける」方針が前提。
> - `contract_conditions`（`agency_id` / `effective_from` / `effective_until`）は R1 実装済み。`orders.contract_condition_id` は必須（旧Laravel負債 T-3 の是正: 契約条件は受注側に紐づける）。
> - 初期費用は `ProductInitialFee`（`product_initial_fees.amount`）→ `orders.product_initial_fee_id`。オプションは `ProductOption` / `OrderOption`。

## 2. 請求ルール（business-flow-analysis §7 の再確認）

| 支払方法 | 手数料（税込） | 請求日 |
|---|---|---|
| 口座振替 | 132円 | 翌月27日（休日は翌営業日） |
| クレジットカード | 132円 | カード会社に準ずる |
| コンビニ振込票 | 484円 | — |

- 対応ブランド：VISA / MasterCard / JCB / AMEX / Diners（**Discover・銀聯は非対応**）
- コンビニ・請求書払いは原則NG
- 支払期限超過 → 事務手数料539円を加算した振込票 → 2ヶ月連続未納で強制解約

### 課金モデル（Q-24 の回答）

- **月額継続課金**で確定的（契約日属月から最低24ヶ月、24ヶ月ごと自動更新）
- 方針MTG⑤「クレカ決済へ誘導、口振の手数料を高く」→ 手数料設計に反映余地

> **brige-crm 実装状況（2026-08-19）**: 支払方法の受け皿は `orders.payment_method`（string 50）・`customers.consolidated_billing`・
> `orders.bundled_billing` / `bundle_target_order_number`（R2 実装済み）。**継続課金・請求データ生成・手数料計算は R5 未実装**
> （継続課金の実行手段は `02` §6-1 のとおりネットムーブ側手段が未確定。請求用受注データCSV出力の実装先 R5/R6 も未確定 = 04 R5 D-P8）。

## 3. 契約期間・解約（方針MTG＋business-flow-analysis §7-2）

| 項目 | 現行 | 方針MTGでの議論 |
|---|---|---|
| 最低利用期間 | 契約日属月から24ヶ月 | ①2年→1年へ変更を議論 |
| 自動更新 | 24ヶ月ごと | 連動 |
| 違約金 | 49,800円 | ②残月×月額へ変更を議論（不可寄り） |
| 手数料戻入 | — | ③6ヶ月以内100%戻入（緩和済み） |
| 無料期間 | 1ヶ月 | — |
| 解約告知 | 前月末日まで | — |

> **設計への示唆**：契約期間・違約金は**まだ議論中**（①②③）。
> 違約金計算ロジック（`release-readiness.md` D-7）は**パラメータ化**し、確定後に値を差し替えられるようにする。
>
> **brige-crm 実装状況（2026-08-19）**: 契約期間・自動更新・違約金・解約告知に関するカラム／ロジックは**未実装（R5）**。
> `orders.contract_start_date` / `terminated_at` / `termination_reason` / `cancelled_at` のみ R2 で受け皿あり。
> 契約単位（`11` フィールド168）・初期構築（169）の対応先未定 = **Q-移18** も R7 持ち越し。
> Q-背3（契約期間・違約金の最終決定）は 04 R5 着手前チェックリスト Q-25（返金・キャンセル）と併せて確定させる。
